维护日期：2026-09-25。[文档索引](README.md) · [当前计划](../task_plan.md)。

足部碰撞现用 SMPL 足部表面凸包，替换会先于皮肤触地的包围盒。质量门改为逐动作检查，
滑步控制现采用世界坐标足部位姿规划：支撑脚保持位置/朝向，摆动脚先抬起再移动，
停车和反向单独预测落点。保留AMASS上身参考、重定向下肢，默认速度仍0.4 m/s。
根外力辅助和真实PhysX接触保留。最新各协议实测及剩余蹲姿/动作问题见
[滑步专项](slip-resolution-2026-09-25.md)，未恢复批量训练数据生成。

## 启动与键位

从任意目录执行：

```bash
~/isaacsim/python.sh /home/gsh/Documents/室内摔倒与机器人救援/scripts/humans/keyboard.py
```

等待人体与窗口出现，点一下 Isaac 窗口获得焦点。默认速度 0.4 m/s，转速 30°/s。
窗口中的 `External root assistance: ON` 表示当前使用外力辅助。

| 按键 | 动作 |
| --- | --- |
| W / 上箭头 | 向人物朝向前进 |
| S / 下箭头 | 后退 |
| A / 左箭头 | 与 W/S 同时按时左转；站立时无效 |
| D / 右箭头 | 与 W/S 同时按时右转；站立时无效 |
| 空格 / 松开方向键 | 减速停止并恢复站姿 |
| C | 蹲下。走路中按下会先自动刹停（`braking_for_action`），再按 `transition_s` 下蹲，最后蹲姿保持 |
| B | 弯腰（CMU/115 源姿势，双脚接触投影落）。同样先刹停再过渡 |
| N | 坐地（Transitions `sit_stand` 源姿势，骨盆/双脚/双手接触投影落） |
| V | 从任一姿势（蹲/弯腰/坐地）起立，完全站直后恢复移动 |
| F | 摔倒。单次触发：关闭根部辅助与位置驱动，沿当前朝向向后打一次有限冲量，之后由 PhysX 自行演化 |
| G | 从倒地状态起身（仅倒地时有效）。回放 CMU/140 躺→站片段：以实测倒地位置和朝向为锚，0.5 s 混入后按片段回放，恢复位置驱动与辅助；摔倒记录不被清除 |
| R | 复位到初始位置，清零速度；这是显式传送。摔倒后可用 G 物理起身或 R 显式复位 |
| Esc / 关闭窗口 | 退出并保存记录 |

C/B/N/V 的移动指令在动作期间被屏蔽；蹲下/起立/摔倒不会因根部高度变化被误标为跌倒，
跌倒标签由实测触发（首次非足部撞地 + 根高低于站立 60% + 倾角大于 50°）。
`report.json` 的 `fall.events` 记录每一次跌倒请求时刻、撞击时刻与躺平时刻，
`fall.requested_time_s` 等摘要字段读的是最后一条事件，因此会话中途按 R 也不会清空它。
`report.json::postures` 保存各姿势的源文件/帧区间与接触投影残差；
`report.json::get_up` 保存起身片段的溯源（时长、帧数、根位移）。

默认输出 `artifacts/humans/keyboard/`。重复运行会覆盖该目录同名产物，可用 `--out` 区分。
`control.npz` 为物理状态、目标、外力和输入，`contacts.json` 为逐帧接触对象/点/冲量，
`recording.npz` 为实际物理姿态蒙皮，`report.json` 为来源和质量门槛。
内存采用有界历史，默认保留最近约 120 s 的控制与显示记录；长时间使用不会无限累计网格。
报告的质量指标仅覆盖保留时间窗，不代表整段任意长会话全部通过。
超过保留窗的会话会在 `complete_recording_window` 门被拒收，不能凭最后一段通过而导出整段训练数据。

诊断动作协议：`--config configs/humans/acceptance_matrix.yaml --demo --headless`。
它固定前进、左右行走转向、后退、蹲/起、摔倒和复位，启用
`record_mesh_at_physics_hz: true`：120 Hz 实际网格与控制同一 pre-step 时间采样，显示仍为 30 Hz。
该选项增加记录开销；普通交互默认保持显示频率采样。质量报告分开记录每个动作和左右行走转向。
另有 `configs/humans/locomotion_acceptance.yaml`：52.7 s反复起停、直接反向、短按键及后退转向。
配置中的 `contact_planner` 与两方向 `contact_cycle` 必须一致，不能同时开启旧 `stance` 控制器。
改动后需重启此脚本；已运行的 Isaac 进程不会自动热加载Python或YAML。

CPU 和自动 GUI 测试：

```bash
python3 scripts/humans/keyboard.py --dry-run --out artifacts/keyboard_control_20260924/cpu
~/isaacsim/python.sh scripts/humans/keyboard.py --demo --capture \
  --out artifacts/keyboard_control_20260924/gui
# --headless 可改为无窗口自动测试；--seconds 可限定运行时长
```

此入口支持移动、转向、站立、复位，以及蹲下/起立/摔倒三个动作键位（2026-09-24 起）。
路线由用户键盘控制，不实现主动避障；碰撞阻挡和接触质量仍须验收。R 是复位传送，不是起立动作。
`keyboard.yaml` 的 `demo` 段只编排 W/SPACE/A/S/R，**不含 C/V/F**，所以自动 demo
不会演练新动作；新动作的实跑证据见下文 47.5 s 全动作会话。

## 工作目标

用键盘驱动物理关节目标和有界根外力，让 SMPL 显示实时 PhysX 姿态。
普通移动、转向和停止不写入根位姿，不绕过墙体碰撞。
先交付明确标记为辅助控制的工具，自主平衡继续作为独立未完成能力。

## 2026-09-24 膝关节外展（"劈叉"）定位与修复

用户实测：正常行走时膝关节动作过大，有时向身体两侧张开。已在 CPU 上复现、归因并修复控制层，
全部数字来自 `scripts/humans/audit_stance_ik.py`（常驻工具）与
`artifacts/humans/stance_ik_audit{,_gate_off}/`、`artifacts/humans/stance_ik_prior_sweep/`。

**归因。** 三级排除：

| 层 | 判据 | 结果 |
| --- | --- | --- |
| 重定向链 | 把 `x/z/y` 三轴链乘回去与源 SMPL 关节旋转矩阵比测地角 | 19 个关节最大 **0.000°**，逐位忠实，**排除** |
| 参考动作本身 | 纯步态目标的左右膝侧向间距 | 前进 **0.177–0.261 m**（静息髋宽 0.131 m），偏宽但不是劈叉 |
| 支撑脚 IK | 实跑链路重放（teleop 目标 → `stance.correct`） | **0.049–0.375 m**；膝侧向轴单帧最高 **35.02°**、髋 **27.63°**；**93.9%** 的步有腿 DOF 被改 >15°；锚点残差 **170 mm**；修正打满 0.7 rad 预算 |

即症状由 P0-B 的支撑脚约束注入，与 PhysX/PD/根辅助无关（那三层在这个 CPU 重放里根本没参与）。

**被否证的假设。** 曾怀疑"步频与根速度耦合不一致导致锚点漂走"。把根部速度分别取
0.40 / 现役步频 0.777 / 源自身 1.071 m/s，一个支撑窗内落脚点相对触地点的漂移是
**118 / 140 / 139 mm** —— 与速度无关，是参考的几何属性。被标"支撑"的脚在源里自己就没踩住：
中位滑速前进 **0.134**、后退 **0.108 m/s**，已超本项目 0.15 m/s 验收门的帧占 46.8% / 38.1%。

**改动。** `configs/humans/keyboard.yaml` `stance:` 段与 `max_stance_slip_m_s`：

1. `max_correction_rad` **0.7 → 0.087**（5°）。5° 膝屈曲约等于 35 mm 足端位移，与下面的释放门限同量级。
2. 新增 `abduction_weight: 1000.0`，关节空间加权
   `δ = W⁻¹Jᵀ(JW⁻¹Jᵀ+λI)⁻¹e`，被惩罚的 DOF 由 **FK 探针**选出（每弧度侧向位移 ≥0.10 m 且侧向主导），
   命中 `left/right_hip__dof1` 与 `left/right_knee__dof1`。
3. 新增 `release_residual_m: 0.03`：残差超阈值就**放弃锚点**并累计 `anchor_releases`，
   写进 `report.json::stance_control`。踩不住变成一条滑步记录，而不是变形的膝盖。
4. 新增 `max_stance_slip_m_s: 0.15`：只有参考自身踩得住的帧才允许建锚。

**修复后（同一 3 s 按 W 重放）。** 侧向轴注入 **35.02° → 4.98°**（>10° 的步 32–36% → **0%**），
膝间距 **0.169–0.289 m**（目标 0.177–0.261）。单因子回退都复现不出症状：
只回退预算 → 侧向 6.49°；只回退先验 → 膝间距 0.178–0.318 m；两者同回退 → **35.02° / 0.045–0.378 m**，
与修复前逐位一致。`abduction_weight` 取 1000 是扫出来的：侧向注入 4.98°(1) / 4.41°(100) /
**0.53°(1000)** / 0.07°(1e4)，1e3 之后不再改善而锚点更早放弃。

**仍未解决（如实保留）。** 约束现在**不再伤害姿态，但也几乎不成立**：97.5% 的步贴著 5° 预算，
残差仍 **96 mm**，3 s 内释放 **102 次**（关掉新门槛反而 213 次）。结论是
**两条现役 AMASS 片段都不含可保持的落地脚**，靠重定向与增益换不来无滑步。
下一步只有三条路：按"落地可保持性"预筛并换源、把锚点改成随根平移的相对目标、
或直接进入 P0-C 接触感知全身控制。

**顺带修掉一个会让结论反读的标签缺陷。** `gait_seam_audit.py` 的 `AXIS_ROLE` 声称
"x=屈曲 / y=外展"，与 rig 配置头部"x=外展 / y=屈曲"正相反。实测：腿链上两者以 **y 为屈曲**
（30° 使踝前后动 18 cm、左右动 0），**x 为外展**（左右 19 cm）；但臂链的同一个字母又是别的角色，
且**同一字母在程序化静息骨架与 SMPL 静息骨架下结果不同**。所以字母→解剖角色的全局表必然至少
对一条链是错的：该脚本改为**按 FK 实测**输出角色，控制器的惩罚集同样由 `sideways_leg_dofs()`
实测得出，并有 `tests/humans/test_contact_control.py` 钉住。摆臂的比值数字本身是按幅度选轴的，
**未受影响**；只改标签口径，不改行为。

**Isaac 实跑复核**（`artifacts/humans/knee_fix_isaac/`，headless demo 10.3 s 仿真 / 26.3 s 墙钟，
RTF 0.39，1236 物理步 = 1236 控制回调，1 次复位，`errors: []`，`keyboard_sha256` b30e723c）：
新门槛确实生效 —— 前进/后退支撑帧 **188→100 / 168→104**，惩罚集为四条
`{left,right}_{hip,knee}__dof1`，本次会话释放 **197** 次、最大残差 **111 mm**。
最大关节误差 **12.786° → 5.719°**（门槛 15°），皮肤最低点 **+2.98 mm**（门槛 −5 mm 通过），
根辅助峰值 873.3 N → **841.8 N**；脚底滑速 p95 **0.651 m/s**（0.15 门**不过**，比修复前的
0.598 略差，与 CPU 重放的预测一致：约束不再靠变形换取"看起来没滑"）。
注意这两次不是同一实验：47.5 s 那次含蹲/起/摔的人工会话，10.3 s 这次是 demo 序列，
按项目规则不能混成同一轮指标；受控对照以上面的 CPU 重放 A/B 为准。

CPU 门禁：compileall 通过、Ruff 全过、pytest **326 passed / 9 skipped**（新增 6 条）。
视觉确认仍需用户本人在 GUI 里走一段：本仓库的数值门能证明膝不再被掰开，

# 走路一瘸一拐：窗口不是整步幅，补偿项把两腿错开了

维护日期：2026-09-24。工具 `scripts/humans/fit_gait_windows.py`，
证据 `artifacts/humans/gait_window_fit/fit.json`。
[全部文档](README.md) · [当前计划](../task_plan.md)。

## 症状

用户实测反馈：**走起来左腿迈得比右腿大很多**。

## 量出来的缺陷

沿实际发货管线（`gait.sample` + `gait.tilt` + 前向运动学）量每只脚在身体系的
前后行程与平均位置：

| 片段 | 步幅 L/R | 比值 | **两脚平均前后偏置** |
| --- | ---: | ---: | ---: |
| forward（旧窗口） | 570.6 / 648.1 mm | 0.880 | **247.1 mm** |
| backward（旧窗口） | 732.7 / 681.1 mm | 1.076 | **95.8 mm** |

判据是**两脚平均前后偏置**，不是步幅比：左脚平均在骨盆前 108.6 mm、右脚在后 138.4 mm
（forward），也就是**一条腿一直伸在前面、另一条一直缩在后面**——看上去就是「左腿迈得大」。
247 mm 的固定错位在视觉上非常显眼。

## 根因：周期性是靠一条线性斜坡伪造的

`Gait.sample` 这样造出周期参考：

```python
q = interpolate(phase) - phase * (joints[-1] - joints[0])
```

**只有窗口恰好包含整数个步幅时它才无害**，因为那时 `joints[-1] - joints[0] ≈ 0`，斜坡什么也不做。
否则这条斜坡要**真的抵消掉一部分运动**，速率正比于每个 DOF 自己的端点差。

实测：`forward` 的配置窗口（`start_s 0.0` + `duration_s 1.2` = 144 帧）端点差
**16.95°**（最差 `right_hip` 16.95°），`backward` 的 **32.87°**。
**而 08_04 的真实步幅是 ~160 帧 = 1.333 s**（两个独立方法都指向这个值，见下）。

**为什么端点差会变成两腿的固定错位**：两腿相差半个步幅。同一条「相位 × 每 DOF 端点差」
的斜坡函数，对左腿作用在相位 φ、对右腿作用在相位 φ−½，于是它在两条腿的局部周期里
呈现为**符号相反**的准静态偏移——落到几何上就是一脚在前一脚在后的固定错位。
这跟关节限位或增益都无关，它在参考里。

### 真实步幅的两次独立确认

| 方法 | 结果 |
| --- | --- |
| 整段源片段里与第 0 帧最接近的帧 | 帧 160（1.333 s），最大关节差 2.80° |
| 全局周期性（各 DOF 归一化后自距离最小） | 157 帧附近，与端点闭合最优候选一致 |

两个方法都说 **≈1.31–1.33 s，不是 1.20 s**。

## 修复：把窗口拟合到整步幅

`scripts/humans/fit_gait_windows.py`：先用**全局周期性**定期（序列的性质，用整段比用单个起点稳），
再用**端点闭合**选起点（切点才决定闭不闭环），并且**拒绝半步幅**——
判据是「某个候选的 lag-2P 周期性优于 lag-P，说明它是半步幅而不是步幅」。
实测该判据真的拦下了候选（forward 拦下 100–102 帧、backward 拦下 84–86 帧，
它们的 2P 周期性都明显更好）。

所有数字都由**调用 `load_gait` 并覆盖窗口**得到，走的就是发货管线（含补偿项、步频估计、
支撑掩码），不是重新实现。

### 结果

| | forward | backward |
| --- | --- | --- |
| 窗口 | 0.0 s + 1.2 s → **1.9667 s + 1.3083 s**（157 帧） | 0.4 s + 1.2 s → **0.4 s + 1.4833 s**（178 帧） |
| 环路闭合（补偿项要消掉的量） | 16.95° → **1.54°** | 32.87° → **3.33°** |
| **两脚前后偏置** | 247.1 mm → **0.1 mm** | 95.8 mm → **5.2 mm** |
| 步幅 L/R | 0.880 → **1.020** | 1.076 → **0.997** |
| 每周期根前进量 | 932 → 1154 mm | 1298 → 1473 mm |

工具做成幂等的：把拟合值写进配置后再跑，它报出的「configured」与「fitted」逐位相同。

**注意**：这个改动同时改变了每周期根前进量（forward 932→1154 mm），
**所以改动前后的结果不可直接比较**，包括滑速与关节误差的历史基线。

## 未做 / 不得声称

  目标与实际差 ≤ 2.4 mm（跟踪忠实）。本篇以下所有数字仍是参考侧口径。
- 只改了 `forward`/`backward` 两个窗口；`idle` 与 `crouch` 是近静止姿势，不适用。
- 没有筛查整库找「步幅更干净」的片段：本缺陷的根因是窗口不是整步幅，
  换片段不是必需。若日后要换源，本工具可直接用于筛选（判据是端点闭合，不是步态周期长度）。
- 「两脚平均前后偏置」用的是**胶囊/踝的世界 x 均值**，不是真实接触；它衡量的是参考里的姿态错位。
  物理侧是否复现同样幅度的错位，由上面的 A/B 判定（已判定：不复现，残余 4.6 mm）。

## 复现

```bash
python3 scripts/humans/fit_gait_windows.py \
  --out artifacts/humans/gait_window_fit/fit.json
```

只读、CPU、不需要 Isaac Sim。它只测量并打印建议的 `start_s` / `duration_s`，**不改配置**。

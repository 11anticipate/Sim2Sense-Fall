# 起身悬空专项：从「被绳子吊起来」到四肢撑地（2026-09-27）

用户实测缺陷：按 `G` 起身时人一直在空中。本文记录定位过程、两处修复、改前改后
实测与视觉复核，以及仍未过门的边界。

- 诊断工具：`scripts/humans/diagnose_getup_float.py`
- 证据：`artifacts/humans/getup_float/`、`artifacts/diag_getup_closure/{before,after,after2}/`
- 对照图：`artifacts/diag_getup_closure/getup_ab_sheet.png`

## 1. 控制链路（为什么外力能把你抬起来）

键盘只改**目标**，不搬身体。每个物理解算步（1/120 s）产生两类目标：

1. 57 个关节角目标 → 逐关节 PD 力矩（髋 1200/400 Nm 等）。
2. 骨盆（根）位姿目标 → **外力**：`root_control.root_wrench()` =
   位置弹簧 12000 N/m + 阻尼 900 Ns/m + 恒定重力补偿 0.6–0.7 倍体重，
   总力上限 1500 N，垂直提升上限 `max_vertical_lift_fraction_of_weight: 1.0`
   （= 1 倍体重，72 kg × 9.81 = 706 N）。

摔倒 `F` 时这根"绳子"被关掉（实测 `falling/fallen` 段垂直辅助 = 0.00 倍体重），
所以摔倒是真物理。起身 `G` 时 `keyboard.py` 把驱动与辅助全部恢复，然后回放
`CMU/140/140_01`（6.91 s 躺→站）。

## 2. 缺陷一：回放路径的根高是"素材自带的绝对曲线"

`load_action_clip()` 只在片段**第一帧**对一次地（`first_frame_collision_minimum_constant_offset`，
实测偏移 −0.677 m），之后 `heights_m` 直接沿用该 mocap 受试者的骨盆轨迹。
`diagnose_getup_float.py` 逐帧比较"片段根高"与"把当前构型最低碰撞体放到地面所需的根高"：

| 时刻 | 片段根高 | 接触闭包根高 | 差（片段浮空量） |
| --- | ---: | ---: | ---: |
| 0.0 s | 0.229 | 0.229 | 0.000（首帧已对地） |
| 2.5 s | 0.518 | 0.424 | 0.094 |
| 4.5 s | 0.989 | 0.857 | 0.132 |
| 6.91 s（末帧） | 0.937 | 0.819 | **0.118** |

830 帧**全部**浮空，中位 87.6 mm、最大 142.6 mm。脚在 10–19 cm 之上，没有任何东西能推地，
唯一能把身体抬到那条曲线上的就是骨盆外力——它立刻顶到 1.0 倍体重的上限。

实测（`artifacts/diag_getup_slerp`，出厂代码）：起身段左脚接触 2.8%、右脚 0.1%，
地面法向力中位 **0 N**，垂直辅助中位 **1.00 倍体重**（888 帧里 637 帧 ≥0.95 W），
最长无支撑 3.89 s。用户看到的"在空中起立"就是这一段。

**修复**：`ActionConfig.get_up_contact_closure`（默认开）把 `actions._apply_playback()`
的根高改为接触闭包——逐帧对混合构型做 FK，取所有碰撞体最低点贴地，与
`ActionState.apply()` 早在 09-25 就用于蹲/坐/弯腰的机制同源。

## 3. 缺陷二：限速器在交接时追的是"摔倒前的旧指令"

改完根高，起身段关节误差仍是 114.0°。查 `control.npz` 的交接瞬间：

```
fallen 末帧   cmd right_knee =  18.5°   meas = 136.4°
G 首帧        cmd right_knee =  22.4°   meas = 136.4°      （限速 8 rad/s = 3.8°/帧）
```

摔倒期间驱动归零，指令停在**冻结的摔倒前站姿**上（膝 18.5°），身体却已被动塌成膝 136°。
`G` 恢复满驱动后，`keyboard.py` 的每步限速器仍以旧指令为锚，于是首帧就下发 22.4°——
身体被 114° 的误差猛拉，腿在半空抽直。

**修复**：`actions.recovery_command_anchor()` + `keyboard.py` 在 `get_up` 交接处把限速锚点
重设为**实测**关节角。动作层本身首帧指令就等于实测位姿（回归
`test_getup_first_command_is_the_measured_body_pose`），所以重设锚点不额外改变行为。

## 4. 改前改后实测（同 seed、同 14 s 协议、120 Hz 原生蒙皮）

协议：1 s 站立 → `F` → 4 s 倒地 → `G` → 6 s 起身 → 3 s 站立。

| 指标（`getting_up` 段） | 门槛 | before | +闭包 | +闭包+限速锚 |
| --- | --- | ---: | ---: | ---: |
| 地面承重中位（倍体重） | ≥0.20 | 0.00 | 0.23 | 0.23 |
| 骨盆外力中位（倍体重） | — | 1.00 | 0.78 | 0.78 |
| 主接触帧占比 | — | 0.45 | 0.91 | 0.92 |
| 最长无支撑 | ≤0.05 s | 2.808 | 0.117 | 0.117 |
| 全身蒙皮最低点 p95 | ≤20 mm | 142.8 | 40.5 | 40.8 |
| 最大关节误差 | ≤30° | 114.0 | 114.0 | **96.9** |
| 主接触滑速 p95 | ≤0.25 m/s | 0.902 | 0.671 | 0.599 |
| `standing_up` 交接滑速 p95 | ≤0.15 m/s | 0.695 | 0.371 | 0.360 |
| `stand` 段 | 全过 | ✗（无支撑 0.058 s） | ✓ | ✓ |

三档是**单因子递进**消融：before = 出厂代码；+闭包 = 只开 `get_up_contact_closure`；
+闭包+限速锚 = 当前代码。`errors: []`、`runtime_completed: true` 三档相同。

## 5. 视觉复核

`renders_follow/` 用同一 `--follow` 相机渲染同一物理时刻。t=9.0 s：

- before：人"坐"在半空，双腿收起乱蹬，影子与身体之间有明显间隙。
- after2：四肢撑地（手掌压地、膝近地）做推起，影子贴身。

t=12.0 s 两档都仍是深蹲前倾姿态——起身末段还没站稳，与蒙皮最低点 p95 40 mm 一致。

## 6. 仍未过门（如实）

`getting_up` 5 项门里仍失败 4 项：无支撑 0.117 s、滑速 0.599 m/s、关节误差 96.9°、
穿地（>5 mm）。根因不是参数而是范式：**回放 + PD 跟踪 + 骨盆外力**无法产生"由接触力
驱动的起身"——素材的关节轨迹与地面约束本来就不相容（09-26 已记："彻底消除需物理起身
或定制素材，库里限位内 0 条仰躺起身"）。闭包与限速锚消除了最刺眼的悬空/抽腿，
但要把起身做到可训练数据级，需要 (a) 降低恢复期垂直辅助上限逼腿出力，或 (b) 物理起身
策略（P0-C 自主平衡，独立课题）。(a) 的 A/B 见 `docs/progress.md` 同日条目。

## 7. 口径变更（预登记，先写后跑）

`MotionQualityConfig` 新增低姿支撑类（`getting_up` / `sitting` / `sit`）：主接触集
（踝/脚/膝/髋/手/腕/肘/骨盆/脊柱）任一贴地即算支撑；全身蒙皮最低点 p95 ≤20 mm；
主接触滑速 ≤0.25 m/s；关节误差 ≤30°；并新增对所有活动生效的
`min_ground_load_fraction: 0.2`（地板必须承担 ≥20% 体重）。脚类活动的
5 mm / 0.15 m/s / 15° 门不变，两套数值同时上报，改口径不藏旧账。
会话级站姿跟踪门按官方规则（"跌倒后的关节轨迹不强制满足站姿跟踪门槛"）把
`getting_up` 排除出 15° 口径，改由上述低姿门单独判。

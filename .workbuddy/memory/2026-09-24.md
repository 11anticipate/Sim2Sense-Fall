## 足部摩擦能否解决滑步（P0-B 子项，只读，未改物理）

用户问「能不能像真实世界一样给脚加摩擦解决滑步」。答：**不能单独解决**，已定量。
新工具 `scripts/humans/audit_friction_budget.py`（CPU、只读已有会话的 `control.npz`+`contacts.json`），
证据 `artifacts/humans/friction_budget/report.json`，文档 `docs/foot-friction-audit.md`。

- **两个新发现的盲区（重要）**：
  1. **人体碰撞体没有任何物理材质**。`human_trial.usda` 的 collider 只有
     `PhysicsCollisionAPI`/`PhysxCollisionAPI`/`PhysxContactReportAPI`，**无 `MaterialBindingAPI`**。
     摩擦走 PhysX 默认 0.5，与地板 0.55 按默认 average 合成 → 有效 μ≈0.525，
     且不进配置、不进 provenance。这也是配置里 `support_loss` 被标未实现的原因。
  2. **摩擦力从未被测量**：`contact_samples` 的 `record.impulse` **只有法向分量**——
     全部归档会话 **3286 个非零样本全部与接触法向平行，最大偏差 2.22e-16**（地板+墙面都算）。
     要直接量摩擦须改用 `isaacsim.sensors.experimental.physics.ContactSensor.get_raw_data()`，
     其 `ContactRawData.impulseX/Y/Z` 是**世界坐标三分量**（Isaac Sim 6.0 文档可证）。
- **方法**：摩擦需求用 `F_c = m(a_COM+g) − F_assist` 反推，`a_COM` 由记录关节角走
  `rig.forward_kinematics` 求质心后两次差分。**正向对照**：重建法向 vs 接触日志实测
  p50 为 **120 N vs 122 N**（cycles）与 **122 N vs 122 N**（v4）→ 方法可信才看横向。
- **cycles 结论**：地面只承担 **0.17 体重**（120 N / 706 N），根部外力竖直 p50 **581 N = 0.82 体重**
  （配置写 0.7，弹簧附加约 87 N）；`mu_required` p50 0.198 / p95 0.674；
  滑动帧 18.4%，其中**只有 24.2% 切向需求 ≥ 上限**，且它们 slip p50 **0.358 < 0.528 m/s**（其余更严重）。
  滑动帧 `mu_required` 直方图在 **[0.5,0.6) 最高单峰**（69/355）→ 数据自认有效系数≈0.525。
- **稳健性**：平滑窗 3/5/9/15/25 帧 → 摩擦受限占比 20.4/24.2/31.4/39.1/44.2%，**最坏也不到一半**。
  反向对照 `actions_final`（辅助关闭）地面承担 1.00 体重、`mu_required` p50 0.004、滑动 1.1%
  （但它只做站立/蹲起，不是干净对照）。`v6/v8` 的 52%/63% 因地面法向 p50 仅 2 N、分母趋零，不作证据。
- **机制**：μN 与 N 成正比，辅助举走 0.82 体重把上限压到真实世界的约 1/5（64 N vs 353 N）；

  转成关节误差或被弹簧拖。加上 P0-B 已归档的「参考自身支撑脚中位滑 0.134/0.108 m/s、残差 111 mm」。

### 补：竖直力平衡自检（回答「地面没承重？」）

不是「不承重」，是被外部执行器顶掉大半。`cycles` 中位数：
- 体重 706 N = 外部执行器竖直 **581 N（0.82 体重）** + 地面反力 **120 N（0.17 体重）**，
  相加 701 N，差 0.7%（身体缓慢竖向加减速）。

  `kp·(target_z − root_z)` 中位数 **89.2 N** = 583.6 N ≈ 实测 581.1 N，相关 0.784。
  **即竖直弹簧把骨盆托得比腿给出的位置更高，多举约 89 N，配置写的 0.7 实际跑成 0.82。**

## 用户实测缺陷：行走一瘸一拐（左腿迈得比右腿大）—— 已修参考构造

- **症状→量化**：两脚平均前后偏置 **forward 247.1 mm**（左 +108.6 / 右 −138.4）、
  backward 95.8 mm；步幅比 L/R 0.880 / 1.076。**判据用前后偏置，不是步幅比。**
- **根因（重要）**：`Gait.sample` 靠线性斜坡伪造周期性
  `q = interp(phase) − phase·(joints[-1] − joints[0])`，**只有窗口是整数步幅时才无害**。
  旧配置窗口 1.2 s = 144 帧不是整步幅（端点差 forward **16.95°**、backward **32.87°**），
  而 08_04 真实步幅 ~160 帧 = 1.333 s。**两腿相差半步幅 ⇒ 同一条每-DOF 斜坡在两条腿上
  呈现符号相反的准静态偏移 ⇒ 两脚固定前后错位。** 这是参考里的缺陷，增益/限位都救不了。
- **修法**：`scripts/humans/fit_gait_windows.py`（新）——全局周期性定期（整段序列），
  端点闭合选起点，**拒绝半步幅**（lag-2P 周期性优于 lag-P 即半步幅；实测拦下 100-102/84-86 帧候选）。
  数字全部由 `load_gait` 覆盖窗口得到，走发货管线。**工具幂等**。
  配置改为 forward `1.9667 + 1.3083`、backward `0.4 + 1.4833`。
  参考侧：闭合 16.95→**1.54°** / 32.87→**3.33°**，错位 247.1→**0.1 mm** / 95.8→**5.2 mm**。

### P0-2 接触通道 — 已修，但归因方案推倒重来

**原方案（建 句柄→prim 路径 映射表）实测不可行，刻意废弃。** 三条证据：

1. 报告结构体里 `proto_index0/1` 是无效哨兵 `4294967295`，**没有路径字段**，
   本机**不存在 句柄→路径 的 API**。`actor = 2×collider − 256` 只是数值巧合。
2. `PhysxContactReportAPI` **按 ACTOR 生效，不按 collider**：
   - 摘掉全部 19 个人体胶囊的该 API → 报告仍是 **6 对 / 8 句柄，一对未少**；
   - 只给任意单个胶囊加上 → 仍是**同样的 8 个句柄**；
   - 摘掉**环境**侧 → 6 → 0，重挂 → 6。
   所以「人体侧有哪些接触」根本无法从报告里筛出来。
3. 报告**落后一个物理步**；连续两次读取会跨越一次 `app.update()`，句柄也在读数间漂移。

**新方案（已落地）：几何包含归因。**
- `_segment_in_volumes(point, volumes)`（模块级，可 CPU 测试）：拿接触点去和
  **实时世界坐标胶囊体积**做包含测试，返回连杆名或 `None`。
- `_capsule_volumes()` **每次调用重算，绝不缓存**（身体每步在动，缓存会把接触
  归到肢体原来所在的位置）。
- `attributed_contact_samples()` 保证**一次报告读取**同时给出点位与连杆名
  （跨步错配的防线）；`human_contact_samples()` / `contact_segments()` /
  `contact_segment_names()` / `contact_support_summary()` 全部走它。
- 归因结果记 `contact_attribution: "geometry"`；含容差
  `CAPSULE_CONTAINMENT_TOLERANCE_M = 0.02`（PhysX 把接触点报在 contact-offset 外壳上）。
- 报告两「侧」的身份**故意不拆**：拆不出来，硬拆就是埋雷。
- `support_surface_height_m()` 取支撑类 prim 包围盒**最高**面，**不假设 z=0**
  （有台阶/架空地板时 z=0 会让上层接触全被误标）。
- `contact_is_support` = 法向朝上（`normal.z > 0.5`）且点高 ≤ support_z + 0.03 m。

## 摔倒 Mesh 采集 + 一个真缺陷 + 一个我自己造的假缺陷

### 真缺陷：SMPL 导入用了「只管 up」的换基，人体被偏航 90°

`up_axis_conversion` 只能保证 up 不变，管不了水平轴。实测原始 pkl：

```
文件帧：X = 横向(左右)   Y = 上   Z = 前
管线帧：X = 前           Y = 左   Z = 上      ← skeleton.py 的 RestSkeleton 文档
```

所以正确换基要绕垂直轴转 90°，而 `up_axis_conversion` 只有 `("y","z")`/`("z","y")`
两个条目，表达不了。旧代码把「文件 X(横向)」映射到「管线 X(前)」，
**up 仍然朝上**，所以它自己的检查通过，人却侧着站。

修法：`body_frame_conversion(up=, forward=, left=)` 吃完整解剖轴三元组，要求
`det = +1` 拒绝镜像；`_derive_body_frame` 从关节实测三元组（pelvis→head 对
hip→knee 交叉验证 up；髋线对肩线交叉验证 left；forward 由右手系定、再用脚尖验证）；
`_check_standing_frame` 拒绝头不在骨盆上方的人体。`_dominant_axis` 删掉；
`up_axis_conversion` **保留**（AMASS retarget 路径只用 up，它是对的）。
证据记在 `SmplModel.source_frame`，现在 loader 报 `up=y forward=z left=x`。

### 我自己造的假缺陷：把 T-pose 的手臂跨度当成了「躺着」

导出网格首帧 extent `[0.3038, 1.8252, 1.7963]`，我读成「躺着的 1.83×1.80」并去
找第二个缺陷。**错的**：那是「厚度 × 臂展 × 身高」，SMPL 是 T-pose，臂展
1.825 m 本来就大于身高 1.796 m（修好后的模板 `[0.2905, 1.7451, 1.7174]` 同样
1.7451 > 1.7174）。**任何 extent 排列都分不出「站着张开手」和「躺着手张开」。**
已在 `docs/mesh-orientation-defect.md` 里明确撤销「缺陷 2」的说法。

教训（与主缺陷同类）：**拿代理量代替解剖问题**。判姿态只问两件事：
① 头是否在脚上方（实测 rest 位头 z=+1.5955、踝 z=+0.0907）；
② 全程是否从立到平（`fall_forward_reference` 首帧 z∈[0.031,1.827] → 末帧 z∈[0.466,0.770]）。

### 顺手挖出并修掉的真隐患（在 `fit_mesh_to_rest_joints`）

原实现用**裸 argmin 按行号配对** `mesh.rest_joints` ↔ `plan.rest_joint_positions`。
rig 会把关节缩放到配置身高，而授权的 pkl 保持原身高，所以**正确配对**也会差几十毫米
（踝 53 mm、脚 91 mm）。实测：

| 配置身高 | argmin 配对双射？ | 会返回的 scale | 真实 scale |
| --- | --- | --- | --- |
| 1.60 | 是 | 0.9791 | 0.9791 |
| **1.70（当前配置）** | 是 | 1.0459 | 1.0459 |
| 1.75 | **否** | **1.0794** | 1.0459 |
| 1.80 | **否** | **1.1128** | — |

`joint_row_alignment` 改成：**对应关系取自共用的关节名**（两个数组都按同一个
`SkeletonTopology` 索引，所以 identity 就是按名配对），然后**用关节间距离确认**。
为什么不能用别的东西确认：
- **绝对坐标不行** —— 绕原点缩放会连根一起挪，纯 1.08 缩放会让脊柱关节离网格的
  pelvis 更近；实测这个反例会直接把正确的配对判错。
- **骨向量方向不行** —— 脊柱是共线的，`spine1/2/3` 方向完全相同，方向判别不了。
- **关节间距离可以** —— 对平移不变、按同一常数缩放，且能分开共线关节。
  逐行比较时要**屏蔽掉被测行与配对列**（两者自距恒为 0，否则主导均值）。
`fit_mesh_to_rest_joints` 另外断言残差是纯相似（实测 **0 µm**）。

### 导出闸门：新加的两条「旋转看不掉」的检查

**所有老检查都绕垂直轴旋转不变**（stature 范围、FK 对独立 CPU 链、身高拟合收敛、

`mesh lateral axis 'x'` 对 `links lateral axis 'y'`。**不会失败的检查不算证据。**

## P0-3 与「能不能在 Isaac 里看到动作」是两件事

用户问：是不是要做完 P0-3 才能在 Isaac Sim 里看到人物动作？

**不是。** 两者正交：

- **看得到** 靠 **kinematic replay**：查看器每帧直接写 DOF + 根位姿并清零速度，根本不跑
  控制环。P0-3 不在链路上。
- **P0-3 管的是「物理自己能不能站住」**：`simulate.py` 稳定期每步 `set_root_pose` 传送
  骨盆来「按住」人体（`settle_used_root_support`），释放后 PD 撑不住 → 自由落体 →
  `stand_neutral` 被标成 `fall`。这影响的是**自由根试验**(`physics_trial`)。

### 真正的缺口：查看器只认 AMASS（已修）

`view_amass.py` 的回放循环**本来就与动作来源无关**（只调 `clip.rotation_of` /
`root_rotation` / `root_translation` / `resample`），唯一绑死 AMASS 的是 `_screened_library`
（`--amass-root` 是 required）。而 `load_motion_library(configs/humans/motions.yaml)`
返回的是**同一个 `MotionClip` 类型**。所以：

- `--amass-root` 改为**可选**；省略则读内置库。
- `--fall-only` 判据随来源变：有 AMASS 用筛选器，否则用库自身的 `fall_reference` 标签
  （与 `collect_fall_mesh.py --fall-only` 同一判据）。脚本动作 provenence 不是 AMASS，
  `screen_amass_clip` 按设计会抛错，**不能**对它跑筛选器。
- 输出文件名与报告横幅随来源分开（`motion_preview.usda` / `amass_preview.usda`），
  不允许报告写「AMASS preview」却在播脚本动作。
- 没重命名文件：`view_amass` 被 8+ 处文档引用，改名会churn一片。

### 顺手挖出的真问题：`verify.py` 的「不发散」判据原来是在测缺陷

原判据：无驱动自由落体后骨盆水平位移 ≤ **固定 1.0 m**。

- **修复前 PASS 是巧合**：人体被偏航 90°，倒向 0.52 m 外那面墙，被墙挡住 → 0.4263 m。
- **修复后 FAIL**：人体按应有的方向倒，位移 **1.3855 m**。

用探针实测（`/tmp/s2s-drop-probe.py`，逐帧打印骨盆轨迹）：

```
direction = -2.0 deg from +X        ← 正好是管线的前向 +X
horizontal displacement = 1.3855 m  (dx +1.3846, dy -0.0495)
final pelvis height     = 0.3029 m  ← 躺平
x 轨迹: 0.057 0.127 0.394 0.659 0.899 1.199 1.362 1.385 1.385 …
```
**这是帧修复正确的又一个独立佐证**（人体朝 +X 倒），不是新 bug。

改成断言它名字真正声称的两件事（发散的人体两件都违反）：
1. **会停下来** —— 末段 200 ms 爬行实测 **0.005 mm**；
2. **不会跑到比自身体型可达的更远** —— 倒伏把骨盆沿一条不超过站立高度的弧转过去，
   所以界是 `DIVERGENCE_HEIGHT_FACTOR = 2.0` × 站立骨盆高度 = **2.0253 m**（留出撞地滑移）。

界由**实测站立高度**推出，不是照着观测值调；旧常数写进注释防止被复原。

**顺带定位到 P2-1**：`scene_spawn_point` 选「离家具最远」的点，落到客厅 (9.320, 0.520)，
而客厅 bounds x 8.800..18.480 / y 0.000..6.600 → **离 −X 与 −Y 墙各只有 0.52 m**。
向前(+X)倒有 9.16 m 空间，但倒向 ±Y 就会在 0.5 m 处撞墙。需要空间的动作/试验
（摔倒采集尤其）都会受它影响。

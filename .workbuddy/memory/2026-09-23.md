### P0-2 接触通道 — 已修，但归因方案推倒重来

**原方案（建 句柄→prim 路径 映射表）实测不可行，刻意废弃。** 三条证据：

1. 报告结构体里 `proto_index0/1` 是无效哨兵 `4294967295`，**没有路径字段**，
   本机**不存在 句柄→路径 的 API**。`actor = 2×collider − 256` 只是数值巧合。
2. `PhysxContactReportAPI` **按 ACTOR 生效，不按 collider**：
   - 摘掉全部 19 个人体胶囊的该 API → 报告仍是 **6 对 / 8 句柄，一对未少**；
   - 只给任意单个胶囊加上 → 仍是**同样的 8 个句柄**；
   - 摘掉**环境**侧 → 6 → 0，重挂 → 6。
   所以「人体侧有哪些接触」根本无法从报告里筛出来。
3. 报告**落后一个物理步**；连续两次读取会跨越一次 `app.update()`，句柄也在读数间漂移。

**新方案（已落地）：几何包含归因。**
- `_segment_in_volumes(point, volumes)`（模块级，可 CPU 测试）：拿接触点去和
  **实时世界坐标胶囊体积**做包含测试，返回连杆名或 `None`。
- `_capsule_volumes()` **每次调用重算，绝不缓存**（身体每步在动，缓存会把接触
  归到肢体原来所在的位置）。
- `attributed_contact_samples()` 保证**一次报告读取**同时给出点位与连杆名
  （跨步错配的防线）；`human_contact_samples()` / `contact_segments()` /
  `contact_segment_names()` / `contact_support_summary()` 全部走它。
- 归因结果记 `contact_attribution: "geometry"`；含容差
  `CAPSULE_CONTAINMENT_TOLERANCE_M = 0.02`（PhysX 把接触点报在 contact-offset 外壳上）。
- 报告两「侧」的身份**故意不拆**：拆不出来，硬拆就是埋雷。
- `support_surface_height_m()` 取支撑类 prim 包围盒**最高**面，**不假设 z=0**
  （有台阶/架空地板时 z=0 会让上层接触全被误标）。
- `contact_is_support` = 法向朝上（`normal.z > 0.5`）且点高 ≤ support_z + 0.03 m。

**GC 复验（`verify.py`，31 PASS / 0 FAIL）关键三行**：
```
[PASS] contact channel is readable -- 2 pairs on the probe step, source physx_contact_report
[PASS] reported contact points resolve to body limbs -- attribution=geometry, limbs=['left_ankle', 'right_ankle']
[PASS] support surface height is readable -- 0.5 m
```

**试验复验（`--trial stand_neutral:none`）**：`.contacts.npz` 有
**632 行接触、覆盖全部 121 帧**，`contact_segment` 实际取到
`left_ankle / right_ankle / right_shoulder`；`contact_is_support` 正确区分
踝部静置（True，法向 (0,0,1)，separation −3e-5）与肩部撞击（False）。

### 新发现的两个缺陷（未修，待处理）

1. **`support_surface_height_m` 报 0.5 m，但场景里所有 floor/ground prim 顶面
   都 ≤ 0.000 m**（脚本对 7 个 prim 逐个算过：foundation −0.120，6 块 floor 全 0.000）。
   0.5 m 的来源待定位 —— 指向 `_support_paths()` 的
   `"floor"/"ground" in path` 子串兜底分支误收 / `ComputeWorldBound` 读数异常。
   **这个值会污染 `contact_is_support`，必须先查清。**
2. **`stand_neutral`（站立动作）仍被标成 `fall`**：`peak_descent_speed 6.20 m/s`、
   `root_travel 1.14 m`、`final_trunk_angle 95.9°`、`min_body_point_z −0.0406 m`
   （穿地 41 mm）。根因是稳定期每步 `set_root_pose` 释放后 PD 驱动撑不住姿态 →
   自由落体。这正是 **P0-3**（有界支撑力 + 平滑释放 + 记 `settle_support_kind` /
   `settle_released_at_s`），**未开工**。

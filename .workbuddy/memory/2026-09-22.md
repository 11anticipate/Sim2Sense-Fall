### 关键设计决定

- 关节映射：SMPL 的蒙皮链 `G_child = G_parent @ [R_child | J_child − J_parent]` 说明旋转轴
  始终与静止姿态对齐，因此 USD 转动关节只要局部朝向单位阵 + `localPos0` 为静止骨向量
  即可逐字复现，无需坐标系换算。CPU 正运动学是同一链的独立实现，用于反向校验物理结果。
- 每个关节单轴：一个 USD 转动关节只有一个自由度；多轴关节展开成串联 proxy 连杆（已实现、有单测、
  **未在 Isaac 中运行**）。
- 事件标注只用轨迹：扰动不等于标签；躯干倾角取骨盆→颈部实测方向而非根朝向（弯腰时根不转）。
- 时间轴：物理步长与信道采样率分开配置（120 Hz / 50 Hz，非整数比），方法写入产物。
- 辅助必须显式：`settle_used_root_support` / `root_pinned_during_trial` / `root_reference_tracked`。

## 追加四：AMASS CMU 下载失败根因 + 已成功落地 1.99 GB

用户提供浏览器复制的 cURL（带 `PHPSESSID`），据此定位并完成下载。

### 根因（实测，不是推测）

1. **浏览器端无法续传**：`download.php?domain=amass&sfile=...` 未带会话时返回 AMASS 网站 HTML
   （不是文件）。带会话后返回 `206 Partial Content` + `Accept-Ranges: bytes` + 总长
   `1993171135`。服务器**支持**断点续传，是浏览器下载器不会续传，2 GB 单流一旦中断就整体作废。
2. **本轮踩的坑（工程侧）**：
   - `curl -C <offset>` 与 `-r <range>` **不能同时用** → `curl: (33) HTTP server doesn't seem
     to support byte ranges`。
   - `curl --retry` 在传输中断（error 18）重传时**从区间起点重新请求**，但已写入的字节仍在
     追加文件里 → 分片数据重复、体积超出（p3/p6 曾溢出 80 MB）。**必须 `--retry 0`，
     由外层循环按实际 `stat` 大小重新计算 Range。**
   - 两个脚本实例并发写同一 part 文件会造成同样错位 → 加了 `/tmp` 锁文件并在启动前确认无残留 curl。
   - `pkill -f <脚本名>` 会匹配到当前 shell 自身导致命令被 SIGTERM；用 `pgrep` + 排除 `$$` 代替。

### 已完成

- 8 路分段并发（每路 ≈249 MB）+ 逐段大小校验 + 合并：`data/humans/_incoming/CMU.tar.bz2`
  **1,993,171,135 字节**，与服务器声明一致；`bzip2 -t` **完整性通过**（耗时 1m47s）。
- 解压到 `data/humans/amass_raw/CMU/`：**2088 个 `*_poses.npz`、4.4 GB**（2192 个 tar 条目）。
- 抽样验证：`load_amass_clip('CMU/38/38_03_poses.npz')` → 761 帧、120 fps、
  `provenance.kind=amass`、`source_id=amass:38`、license 正确落为 AMASS 非商业科研许可。
- `git check-ignore` 确认 `data/humans/` 已被忽略（第 20 行），不会入库。
- 分片临时文件已清理，`_incoming/CMU.tar.bz2` 保留作归档。

## 人体—世界物理交互审计（新增 docs/physics-interaction-audit.md）

方法：读代码 + 本机 Isaac Sim 6.0.1-rc.7 headless 实跑 + 9 个一次性探查脚本
（都在 `/tmp/s2s-audit/`，未入库）。

**先纠正前提**：物理交互是存在的。`~/isaacsim/python.sh scripts/humans/verify.py`
本轮 **31 PASS / 0 FAIL，退出码 0**；抬高 0.25 m 后骨盆真的下落 1.3079 m。
「完全没有物理」不成立；不成立的是「稳定」与「可观测」。

### 新定位的 P0 根因

1. **出生点混淆两种坐标约定（最重要，之前没人发现）**
   `rig.py:815-848` 把「体坐标系到地面的偏移」`ground_offset_m = 1.246231` 直接当成
   「骨盆连杆世界 z」写进 `spawn_root_position[2]`。骨盆静止 z = −0.233593，
   所以每次出生都**悬空 0.2336 m**（CPU FK 实测 +0.233594，实时刻 t=0 最低胶囊 +0.196150）。
   连带：`simulate.py:341/:906` 把该值当站立骨盆高传给标注器，
   使 `pelvis_height_fraction=0.55` 实际算成 0.685427 而不是 0.556951，**跌倒阈值偏松 0.1285 m**。
   `verify.py:142-152` 的「最低胶囊在 z=0」检查用的是体坐标系 + ground_offset，
   从不用 `spawn_root_position`，所以它 PASS 掩盖了这个 bug。
   修法：`ground_offset` 改由 `forward_kinematics(plan, {}, (0,0,0))` 求，让偏移就是根连杆 z。

2. **接触在全部入口不可读，且 `omni.physics.tensors` 在本机建不起来**
   默认 `enable_contact_views=False`（`usd_human.py:686`），四个入口无一打开。
   打开后仍然失败：插件报 `Pattern '/World/Human' did not match any rigid contact for filters`，
   `rigid_prim.py:1924 _on_physics_ready → AttributeError: 'NoneType' object has no attribute 'check'`。
   已排除：传感器路径、过滤路径、类别、`max_contact_count`(8/16/64/256)、构造时机(play 前后)。
   **可用替代通道（已实测）**：`omni.physx.get_physx_simulation_interface().get_contact_report()`，
   前提是把 `PhysxSchema.PhysxContactReportAPI` **同时**加到接触对两侧
   （人体 19 胶囊 + 地板 7）。只标人体一侧 = 0 对；两侧都标 = 5 对，
   含接触点 (8.5901, 2.137, 0.0)、法向 (0,0,1)、冲量、separation。
   `actor0/collider0` 返回的是数值句柄，不是 prim 路径，需要自建映射表。

3. **三条运动学绕过通路**：`view_amass.py:224-230`（每帧传送 + 清速度，纯木偶）、
   `build.py:258-259`、`simulate.py:710-715`（稳定期每步 `set_root_pose`，
   对 `root_mode=free` 恒为真 → 「站着」不是地面在支撑）。
